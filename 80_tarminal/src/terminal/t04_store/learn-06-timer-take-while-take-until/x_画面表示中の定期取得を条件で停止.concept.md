# 画面表示中の定期取得を条件で停止

このサンプルでは「完了を受け取る → 次の画面を開く」「3回受け取る → 画面を離れる」という操作を、コードで模擬しています。

## 関数詳細

`timer(0, 100)` が定期取得の起点。`takeWhile(status => status === '処理中', true)` は条件を満たさない「完了」も最後に流してから停止する。
`takeUntil(actions$.pipe(ofType(pageLeft)))` は画面離脱アクションを受けた時点で停止する。

## どういうケースで使用するか

NgRx Effect で画面表示中にジョブの状態を定期取得し、完了または画面離脱でポーリングを終える場合。

## 注意点

`takeWhile` の第2引数を省くと「完了」が後続へ流れない。`takeUntilDestroyed` は破棄時の停止用なので、完了ステータスや画面離脱アクションによる停止はそれぞれ別に指定する。


--- AI会話

`takeWhile()` と `takeUntil()` は、どちらも「Observable の購読を途中で終了させる」ための operator ですが、終了条件の考え方が違います。

| Operator      | いつ終了する？                | 条件の種類    | 典型用途                   |
| ------------- | ---------------------- | -------- | ---------------------- |
| `takeWhile()` | 流れてきた値が条件を満たさなくなったら終了  | 値を見る     | `value < 100` の間だけ受け取る |
| `takeUntil()` | 別の Observable が通知したら終了 | 別イベントを見る | destroy、キャンセル、停止ボタン    |

たとえば、

`1 → 2 → 3 → 4 → 5`

に対して、

`takeWhile(x => x < 4)`

なら、

`1 → 2 → 3 → complete`

です。`4` が来た瞬間に「条件を満たさない」と判断して終了します。

一方 `takeUntil(stop$)` は、元の値そのものには条件を付けません。

`source$: A → B → C → D → E`
`stop$:          X`

なら、

`結果:    A → B → C → complete`

です。`stop$` が何か1つ通知した瞬間、`source$` の購読を終了します。

Angularで特によく見るのは `takeUntil()` 系です。昔は `destroy$` を自分で作って、

`source$.pipe(takeUntil(this.destroy$))`

と書いていました。

Angular 16以降では、コンポーネント破棄時の終了なら基本的に、

`source$.pipe(takeUntilDestroyed())`

を使うので、手動の `destroy$ + takeUntil()` はかなり減っています。

覚え方はこれで十分です。

**`takeWhile` = 「この値の条件が成り立つ間」**
**`takeUntil` = 「あっちから停止通知が来るまで」**

なお、`takeWhile` には `inclusive: true` 相当の指定もあり、「条件を外れた最後の1件も含める」という使い方もできます。これは少し特殊なので、まずは上の違いを押さえれば十分です。

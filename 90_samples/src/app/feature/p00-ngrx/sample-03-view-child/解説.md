# `#ref` / `viewChild()` / `viewChildren()` の解説

このサンプルは、親コンポーネントからテンプレート内の子コンポーネントを見つけて、子の値やメソッドを使う方法を試すページです。

コンポーネントの関係は次のとおりです。

```text
Sample03ViewChild（親）
└─ WorkspacePanel（子）
   ├─ TaskCard: 最初のタスク（孫）
   └─ TaskCard: 条件付きの追加タスク（孫）
```

## まずは3つの使い分け

| 方法 | 参照できるもの | このサンプルでの用途 |
| --- | --- | --- |
| `#ref` | テンプレート内で名前を付けた要素・コンポーネント | `#workspaceRef` から復元処理を呼ぶ |
| `viewChild()` | 子コンポーネントを1件 | 親から `WorkspacePanel`、子から「最初のタスク」を取得する |
| `viewChildren()` | 同じ種類の子コンポーネントを複数件 | 表示中のすべての `TaskCard` を取得する |

## `#ref`：テンプレートの中だけで直接使う

`sample-03-view-child.html` では、`WorkspacePanel` に `#workspaceRef` という名前を付けています。

```html
<app-sample-03-workspace-panel #workspaceRef />

<button type="button" (click)="workspaceRef.restoreAll()">
  #ref: すべて元に戻す
</button>
```

この名前はテンプレート内で使えます。ボタンをクリックすると、子コンポーネントの `restoreAll()` を直接呼び出します。

「クリック時に子のメソッドを1回呼びたい」のように、テンプレートだけで書ける短い処理なら `#ref` が分かりやすい選択です。

## `viewChild()`：TypeScript側で子を1件取得する

親の `Sample03ViewChild` では、`WorkspacePanel` を取得しています。

```ts
readonly workspace = viewChild.required(WorkspacePanel);
```

`workspace()` と呼ぶと、画面にある `WorkspacePanel` のインスタンスを取得できます。たとえば、追加タスクの表示・非表示を切り替えるボタンは次のように動きます。

```html
<button type="button" (click)="workspace().toggleExtraTask()">
  追加タスクを表示 / 非表示
</button>
```

`viewChild` が返す値は **Signal** です。そのため、プロパティのように `workspace` と読むのではなく、`workspace()` のように呼び出します。

`required` は「この子は必ず画面にある」という宣言です。このサンプルでは `WorkspacePanel` を常に表示するため使えます。`@if` などで子が表示されたり消えたりする場合は、`viewChild()` を使い、存在しない場合も扱えるようにします。

## 子からさらに子へたどる例

`WorkspacePanel` も、テンプレート内の「最初のタスク」を取得しています。

```ts
readonly primaryTask = viewChild.required<TaskCard>('primaryTask');
```

対応するテンプレートでは、対象に `#primaryTask` を付けています。

```html
<app-sample-03-task-card #primaryTask title="最初のタスク" />
```

このため親は、`WorkspacePanel` を経由して孫の `TaskCard` を操作できます。

```ts
this.workspace().primaryTask().archive();
```

流れは「親 → 子 → 孫」です。画面上の「最初のタスクをアーカイブ」ボタンを押すと、その `TaskCard` の `isArchived` が `true` になり、表示が「アーカイブ済み」に変わります。

## `viewChildren()`：表示中の子をすべて取得する

`WorkspacePanel` では、すべての `TaskCard` を取得しています。

```ts
readonly taskCards = viewChildren(TaskCard);
readonly taskCount = computed(() => this.taskCards().length);
```

ここでも `taskCards()` は Signal です。返される配列には、**その時点で画面に表示されている** `TaskCard` だけが入ります。

```html
@if (showExtraTask()) {
  <app-sample-03-task-card title="条件付きの追加タスク" />
}
```

追加タスクを表示すると `taskCards()` は1件から2件へ自動で変わり、`taskCount` も更新されます。`archiveAll()` と `restoreAll()` は、この配列を順に処理して全タスクの状態を変えています。

```ts
this.taskCards().forEach((task) => task.archive());
```

## 実務で気を付けること

`viewChild()` や `#ref` は、子の操作が必要な場面で便利です。一方で、親が子の内部に強く依存すると、部品の再利用や変更が難しくなります。

親子でデータを渡すだけなら、基本は `input()` と `output()` を優先します。子に「何をしてほしいか」を伝える必要がある場合は、入力値で状態を表せないか、サービスや状態管理に置けないかも検討します。

このサンプルの「親 → 子 → 孫」の呼び出しは、`viewChild` の動きを理解するための例です。実際の画面では、このような深い参照連鎖を増やし過ぎないようにします。

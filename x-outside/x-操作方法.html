00最初に開くURL

起動しても何も出ないのは正常です。トップページ / は ClearML の ダッシュボードにリダイレクトしますが、ClearML Server は起動していないため ログインできず、左サイドナビの「BM」アイコンも表示されません。製造画面には URL で直接入ります。

ここを開く

http://localhost:4200/manufacturing
Mac など別端末からは http://<WindowsのLAN IPv4>:4200/manufacturing

製造画面は ClearML のログイン状態とは無関係に動きます。ヘッダーもサイドナビも使わず、 /manufacturing 配下だけで完結する独立したシェルを持っているためです。

開く前の起動確認

curl http://127.0.0.1:8010/health/ready   # {"status":"ok","database":"ready"}
curl -I http://127.0.0.1:4200/           # HTTP/1.1 200 OK

ブラウザからの API は Angular 開発サーバーが中継します （/bm-api/v1/... → 127.0.0.1:8010/v1/...）。 8010 番をブラウザに公開する必要はありません。

02Overview — 工場の現在地

/manufacturing/overview  ·  API: GET /v1/overview

最初に開く画面です。上段の指標カード4枚、中段の工程分布と健全性、下段の直近の工程実行テーブルという構成になっています。

操作手順

  1. 指標カードをクリックして掘り下げる。「Active work orders」「Lots on hold」「Published products」の3枚はリンクです。 Cells in process だけはリンクではありません。
  2. Route position で滞留を見る。工程コード（LOT-RELEASE / SLURRY-MIX-C / FORMATION-AGE / EOL-GRADE）ごとに 現在いるロット数が並びます。横棒の長さは件数 × 28% で描かれる相対表示です。
  3. Recent process runs で異常を拾う。Run status と Quality の色付きチップが赤／橙なら、 Quality 画面か Work Order 詳細で追跡します。初期データでは ON_HOLD の RUN-EOL-260902-002 が該当します。

リリース操作（実際にデータが変わります）

  1. /manufacturing/work-orders/wo-004 を開きます。状態が DRAFT のときだけ 「Release work order」ボタンが押せます。DRAFT 以外では常に無効です。
  2. ボタンを押すと POST /v1/work-orders/wo-004/release が飛びます。ヘッダーには If-Match: 1（楽観ロック用の版数）、Idempotency-Key（毎回新しい UUID）、 X-BM-Roles: PRODUCTION_MANAGER が付きます。
  3. 成功すると画面上の状態チップが RELEASED に変わり、 Aggregate version が 1 → 2 に上がります。ページ全体の再読み込みは行われません。
  4. 以後ボタンは無効になります。この操作は画面からは戻せません。再度試すにはデータの初期化が必要です（§10）。
エラーが出たとき

「Release was rejected. Refresh the aggregate version and retry.」は、 版数の不一致（409 VERSION_CONFLICT）か、DRAFT 以外への遷移（409 INVALID_TRANSITION）、 またはロール不足（403）です。ブラウザを再読み込みして最新の版数を取り直してから、もう一度試します。

見どころのある指図

  • wo-004 … Release を試せる唯一の指図。ただしロットが0件なので、下の2つのテーブルは空です。
  • wo-001 … ロット2件（うち1件が ON_HOLD、理由「QG-80: DCIR upper limit」）と 工程履歴が入っています。Process traveler の見本にはこちらが向いています。

06Quality — 品質ゲートの判定一覧

/manufacturing/quality  ·  API: GET /v1/quality/evaluations?result=

操作手順

  1. 上部の3タブで絞り込みます。All results（既定）／Needs review（result=HOLD）／Passed（result=PASS）。 押すたびに API を呼び直します。FAIL だけを見るタブはありません。
  2. All results では HOLD → FAIL → その他の順、同順位内は評価時刻の新しい順に並びます。 つまり先頭行がいちばん対応が必要な判定です。
  3. 行を左から右へ読みます。ゲート ＞ 判定 ＞ 実測値 ＞ 規格範囲 ＞ 評価者 ＞ 処置。 実測値が規格範囲のどちら側に外れたかを見て、Traceability で対象を特定します。

列の読み方

列内容
Gate / subjectゲートコード（QG-20C 粘度、QG-30C 目付、QG-80 EOL）と、判定対象の種別・ID
Result判定チップと重大度（BLOCKING / ADVISORY）
Measurement evidence実測値と単位、その下に要約文
Specification下限 — 上限と、束ねている規格リビジョン（例 QSP-QG80-R09）

08Operations — 未接続であることを見せる画面

/manufacturing/operations ／ /manufacturing/operations/:area

設備接続・SPC・保全・異常検知・バッテリーパスポート・ERP/LIMS 連携の6領域を、 STUB（未接続）と明示したまま並べた画面です。数字を出さずに置き換え境界だけを示すのが目的で、 「stub の結果を品質ゲートやリリース判断に使わない」と画面上に宣言しています。

  1. 6枚のカードのどれかをクリックすると、その領域の STUB 詳細ページへ遷移します （例 /manufacturing/operations/spc）。
  2. 詳細ページでは「現在の挙動」「置き換えポイント」「稼働前に必要なもの （契約テスト・認可スコープ・監査イベント・突合ルール）」が読めます。
  3. 左上の「← Operations」で一覧に戻ります。「Download adapter contract」は未実装です。

URL の :area は何を入れても同じ体裁のページが出ます。見出しはハイフン区切りを 単語頭大文字に変換しているだけなので、/operations/anything-here でも 404 にはなりません。

10困ったとき

症状原因と対処
ログイン画面が出る／サイドナビに BM アイコンがない ClearML Server が未起動のため正常です。/manufacturing を直接開いてください。BM アイコンは ClearML にログインしている間だけ表示されます。
「Manufacturing API is unavailable. Start the service on port 8010 and retry.」 FastAPI が落ちています。bm-services で uvicorn を起動し直し、curl http://127.0.0.1:8010/health/ready で確認します。
「Could not load work orders.」「Quality review queue is unavailable.」 同じくバックエンド側の問題です。ブラウザの DevTools → Network で /bm-api/v1/... の応答コードを確認します。
Release ボタンが押せない その指図が DRAFT ではありません。初期データで DRAFT なのは wo-004 だけです。
データを初期状態に戻したい バックエンドを止めて bm-services/.local/bm-data-hub.db を削除し、再起動します。work_orders が空のときだけシードが流れる作りなので、これで5件の初期データが戻ります。
「Invalid PrimeUI License」バナー 設定不備として扱う仕様です。.env の PRIMEUI_LICENSE_KEY を設定して pnpm start をやり直します。
Mac から 4200 につながらない WSL の 172.x ではなく Windows の LAN IPv4 を使います。スリープ復帰後は Angular を止め、ポートフォワードのスクリプトを実行してから再起動します（x-起動方法.md §3）。

11ステータス語彙と色

チップの色は文字列から機械的に決まります。同じ色なら同じ意味だと読んで構いません。

色該当する値読み方
緑 PASS / COMPLETED / PUBLISHED / RELEASED_PRODUCT / SYNCED 完了・合格。追加の対応は不要
橙 HOLD / ON_HOLD / DATA_ERROR / BLOCKING 止まっている。人の判断待ち
赤 FAIL / FAILED / REJECTED / SCRAPPED 不合格・破棄。後戻りしない結末
青 RUNNING / IN_PROGRESS / PROCESSING / PENDING 進行中。時間が経てば変わる
灰 DRAFT / RELEASED / AVAILABLE / CONSUMED ほか 上のどれでもない中立状態

紛らわしい2つの RELEASED

  • Work order の RELEASED … 指図が現場に出た（着手可能になった）状態。灰色チップ。
  • Entity の RELEASED … セルロットが出荷可能として確定した状態。Traceability 画面で見えます。

また、Run status（工程実行の進み）と Quality（品質判定）は別物です。 実行が COMPLETED でも品質が HOLD なら、そのロットは先へ進みません。

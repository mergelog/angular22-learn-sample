# 静的探索の道具と手順

コードを動かさずに、検索・型・依存グラフで開くファイルを絞る手順を置く。
実行時の観測は [05_実行時観測](05_実行時観測で読む.md) にある。
この二つは対立しない。静的探索で候補を数件まで絞り、実行時観測で一つに確定させるのが速い。

## 1. この環境で使える道具

参考記事のコマンドがそのまま動かない場面が多いので、先に可否を並べる。

| 道具 | 可否 | 用途 |
| --- | --- | --- |
| `rg`（ripgrep 14.1.1） | あり | 全文検索。既定で `.gitignore` を尊重するため `node_modules` を自動で外す |
| `madge` | あり（`npx madge`） | import 依存グラフ、循環検出 |
| `tree` | あり | ディレクトリ構造 |
| `git` | あり | 履歴、差分 |
| `node` / `pnpm` | あり | スクリプト、`package.json` の読み取り |
| VS Code の言語サーバ | あり | 定義へ移動、参照の検索、型の表示、名前の変更 |
| `ast-grep` | **無し** | — |
| `jq` | **無し** | `node -e` で代替する |
| `fd` / `fzf` / `ctags` / `cscope` / `semgrep` | **無し** | `rg` と `find` で代替する |

`sg` というコマンドが `/usr/bin/sg` に存在するが、これは `ast-grep` ではなく
Linux の `setgroups` である。`sg` で AST 検索を打つと、意図しないコマンドが走る。

## 2. rg の使い方

`grep -r` ではなく `rg` を使う。理由は二つある。
`.gitignore` を尊重するので `node_modules`（437 パッケージ）や `dist` が結果に混ざらない。
それと、ファイル種別の指定が短い。

| 書き方 | 意味 |
| --- | --- |
| `rg -n -t ts "語" src` | TypeScript のみ（`.ts` `.tsx` `.cts` `.mts`） |
| `rg -n -t html "語" src` | テンプレートのみ |
| `rg -n -t ts -t html "語" src` | 両方。画面の値の出所を追うときはこれ |
| `rg -n -t css "語" src` | `.css` と `.scss` |
| `rg -l -t ts "語" src` | ファイル名だけ（件数の見積もりに使う） |
| `rg -c -t ts "語" src` | ファイルごとの件数 |
| `rg -n -t ts -A5 -B2 "語" src` | 前後の行も出す |

`--include` は `rg` の引数ではない（`grep` の引数である）。打つと `unrecognized flag` で止まる。

件数を先に数えるのが要点である。
`rg -l` で 3 件なら全部開く。50 件なら検索語を変える。数えずに開き始めると、
手当たり次第に読むことになる。

## 3. 同名ファイルを見分ける

`models.ts` はこのリポジトリに 17 個ある。
うち 16 個は `business-logic/model/{名前空間}/models.ts` で、
残り 1 個が `webapp-common/core/cache/entities-observable/models.ts` である。
親ディレクトリ名だけが違うので、ファイル名検索は決まらない。パスで絞る。

```bash
# 名前だけで一覧して、パスで判断する
find src -name "models.ts"

# 層を指定して探す
find src/app/webapp-common -name "*.reducer.ts"
```

VS Code のファイル検索（Ctrl+P）でも、`models.ts` ではなく
`model/tasks/models.ts` のように親ディレクトリを含めて打つ。

## 4. 文字列で結合された箇所を追う

型で結ばれていない結合は、エディタの「定義へ移動」が効かない。検索で追うしかない。

### 4-1. NgRx の Action

Action 名が分かっているときは、**修飾を付けずに素の名前**で検索する。
Reducer は `on(actions.setExperimentLog, ...)` のように名前空間付きの別名で参照しており、
`on(setExperimentLog` では当たらない。

```bash
rg -n -t ts "setExperimentLog" src
```

一回の検索で、定義（`createAction`）・Reducer（`on(...)`）・Effect（`ofType(...)`）・
dispatch 元がまとめて出る。一回の検索で経路の全段が揃うのは、この形だけである。

### 4-2. DevTools に出ている Action 文字列から

Redux DevTools に `[select model] set models` のような文字列が出る。
この文字列を丸ごと検索すると 0 件になる。
`createAction` の引数がテンプレートリテラルで組み立てられている箇所が 23 件あるためである
（`SELECT_MODEL_PREFIX` が 21 件、`USERS_PREFIX` が 2 件）。

角括弧の部分を捨て、後半だけで検索する。

```bash
# 0件: rg -n -t ts "\[select model\] set models" src
rg -n -t ts "set models" src
```

当たるのは `select-model.actions.ts:12` の
`` createAction(`${SELECT_MODEL_PREFIX} set models`, …) `` である。

### 4-3. プレフィクス定数

プレフィクス定数は、同じ名前で別の値が複数定義されている。
定数名ではなく**値**で検索する。

```bash
# 値で探す（定義箇所が一意に決まる）
rg -n -t ts "'\[Experiments Info \]'" src
# 定数名で探すと複数出て、どれか分からない
rg -n -t ts "EXPERIMENTS_INFO_PREFIX = " src
```

### 4-4. テンプレートからクラスへ

コンポーネントのセレクタは `sm-` 接頭辞でほぼ統一されている。
`src` 全体の `selector:` 記述 379 件のうち 345 件が `sm-` で始まる。
残りは属性形式のディレクティブ（`[...]`）が 29 件と、
取り込んだ通知ライブラリの `notifier-*` 2 件、`al-drawer` 1 件などである。
テンプレートで見つけたタグから実装へ移るときは、セレクタ宣言を検索する。

```bash
rg -n -t ts "selector: 'sm-experiments-table'" src
```

逆に、クラスからテンプレートでの使用箇所を探すときはタグ名で引く。

```bash
rg -n -t html "<sm-experiments-table" src
```

### 4-5. ルートから画面へ

URL のパス片で検索する。

```bash
rg -n -t ts "path: 'experiments'" src
```

`app.routes.ts` は `loadChildren` で遅延読み込みしているので、
ルート定義は機能ごとの `*.routes.ts` に分かれている（18 ファイル）。
一段目で当たらなければ、`find src -name "*routes*.ts"` で全部出して読む。

## 5. 依存と参照を見る

### 5-1. 誰がこれを使っているか

VS Code の「参照の検索」（Shift+F12）が第一選択である。
型で結ばれている参照はこれで全部出る。

型で結ばれていない参照（DI、Action、テンプレート）は出ないので、
§4 の検索を併用する。

図で見たいときは、リポジトリ内のスキルを使う。

```bash
node .claude/skills/madge-to/scripts/madge-to.mjs src/app/.../xxx.component.ts
```

`madge-rdeps-{クラス名}.md` が出力される。
Mermaid の図と、宣言行へのリンク一覧が入る。既存例が `madge-rdeps-InlineEditComponent.md` にある。

### 5-2. 死んでいないか確かめる

読み始める前に参照数を数える。

```bash
# import されているか（自分自身を除く）
rg -l -t ts "experiment-shared.config" src | grep -v "experiment-shared.config.ts"
```

出力が空なら、そのファイルは誰からも読み込まれていない。
実際に `src/app/features/experiments/shared/experiment-shared.config.ts` は空になる。
このファイルを 60 行読む価値は無い。

### 5-3. コンポーネントの親子

Angular コンポーネントの関係ツリーは `ngmaze` スキルで出す。

```bash
npx mergelog/ng-maze ExperimentsComponent --mdh
```

出力例が `ng-maze-ExperimentsComponent-20260917-161335.md`（53KB）にある。
出力が大きいので、目的を持って開く。

### 5-4. 循環を先に知る

```bash
npx madge --ts-config tsconfig.json --extensions ts --circular src/app
```

35 件出る。実行に 3〜5 分かかるので、結果はファイルに保存して使い回す。

## 6. 型を道具として使う

### 6-1. 型検査を走らせる

```bash
pnpm run web:typecheck:strict
```

`tsconfig.json` は `strict: false` なので、通常のビルドでは型の穴が検出されない。
`tsconfig.strict.json` 側で厳しく検査する構成になっている。

型が緩い影響は読みにも出る。`: any` が 683 箇所、`as any` が 55 箇所あり、
その箇所では型から実際の形が読み取れない。
`any` に出会ったら、型ではなく実行時の値で確かめる（[05_実行時観測](05_実行時観測で読む.md) §5）。

### 6-2. エディタで型を見る

値の上にカーソルを置いて型を表示させるのは、Reducer の `State` 形状や
Selector の戻り値を知るいちばん速い方法である。定義を辿るより速い。

### 6-3. 型から実装へ

インターフェースの実装クラスを探すときは、`implements` を検索する。

```bash
rg -n -t ts "implements RouteReuseStrategy" src
```

## 7. 境界規則を読む

本リポジトリには import の禁止規則が宣言として置かれている。

```bash
# 違反の一覧（判定はしない）
node scripts/web-boundaries.mjs report
```

`web-boundaries.json` には規則の意図が日本語で書いてある。
「feature は他の feature を直接 import しない」「生成された API に触れるのは境界ファイルだけ」など、
設計の意図がそのまま読める。設計意図を探すなら、この宣言が一次情報になる。

## 8. 命名規約を索引として使う

このコードベースは接尾辞の規約が効いている。役割が分かれば、接尾辞で範囲を絞れる。

| 接尾辞 | 数 | 中身 |
| --- | --- | --- |
| `.component.ts` | 348 | コンポーネント |
| `.pipe.ts` | 77 | パイプ |
| `.service.ts` | 58 | サービス |
| `.actions.ts` | 48 | NgRx の Action |
| `.spec.ts` | 48 | テスト（`src/app` 配下のぶん） |
| `.reducer.ts` / `.effects.ts` | 41 / 41 | NgRx |
| `.directive.ts` | 36 | ディレクティブ |
| `.providers.ts` | 20 | 機能ごとの構成 |
| `.model.ts` / `.routes.ts` | 19 / 17 | 型 / ルート |
| `.consts.ts` / `.utils.ts` / `.guard.ts` | 16 / 12 / 12 | 定数 / ユーティリティ / ガード |
| `.selectors.ts` | 5 | Selector（ただし Reducer 内に書かれているものも多い） |

ディレクトリ名にも規約がある。
`containers/`（14）は状態に接続するコンポーネント、`dumb/`（5）と `components/`（5）は表示専用、
`actions/` `reducers/` `effects/`（各 7）は NgRx である。

```bash
# 役割で絞る
find src/app -name "*.effects.ts"
find src/app/features -name "*.providers.ts"
```

### 8-1. 表記ゆれに注意する

規約は完全ではない。同じ意味に複数の綴りがある。

| 揺れ | 実例 |
| --- | --- |
| `const` / `consts` / `constants` | `experiments.const.ts` / `experiments.consts.ts` / `experiments-compare.constants.ts` |
| 単数 / 複数 | `webapp-common/experiments/experiment.consts.ts` と `features/experiments/experiments.consts.ts` |
| 綴り誤り | `experiment-ouptut/`（"output" の誤り）が両層に存在する |
| 綴り誤り | `highlited`（11 箇所）と `highlighted`（33 箇所）が共存する |

「output」で検索しても `experiment-ouptut/` は出ない。
「highlighted」で検索しても、実験一覧のハイライト状態（`highlited`）は出ない。

**回避** — 当たらないときは、綴りを疑って部分一致で打ち直す。

```bash
rg -n -t ts "highli" src | head      # 両方の綴りを拾う
find src -type d -name "*ou*put*"    # ouptut / output の両方
```

## 9. エディタの操作

検索コマンドより速い操作がある。VS Code での対応は次のとおり。

| やりたいこと | 操作 | 使う場面 |
| --- | --- | --- |
| 定義へ移動 | F12 | 型で結ばれている参照 |
| 定義を覗く（移動しない） | Alt+F12 | 深さを増やさずに中身を確認する |
| 参照の検索 | Shift+F12 | 影響範囲の一次調査 |
| 呼び出し階層 | Shift+Alt+H | 呼び出し元を木で辿る |
| ファイルを開く | Ctrl+P（パスの一部を含めて打つ） | 同名ファイルが多いので、パスで絞る |
| シンボルへ移動（ファイル内） | Ctrl+Shift+O | 大きいファイルの目次になる |
| シンボルへ移動（全体） | Ctrl+T | クラス名は知っているがパスを知らないとき |
| 戻る / 進む | Alt+← / Alt+→ | 潜ったあと確実に浮上する |
| 型を表示 | 値にカーソル | `any` でない箇所なら、定義を辿るより速い |

深さの制御には `Alt+F12`（Peek）と `Alt+←`（戻る）の二つを使う。
Peek なら開いたファイルが増えないので、そもそも戻る必要が出ない。

エディタ側の検索除外は `.vscode/settings.json` で設定済みである
（`node_modules`、`dist`、`build`、`.angular`、`.venv`、`reports`、`test-results` ほか）。
シェルからの検索にはこの設定は効かないので、`rg` を使う。

## 10. 検索が当たらないときの順序

当たらない原因は、だいたい次の順で多い。上から順に疑う。

| 順 | 原因 | 確かめ方 |
| --- | --- | --- |
| 1 | 検索範囲が違う（`src` 外、テンプレート側） | `-t ts -t html` を両方付けて打ち直す |
| 2 | 文字列が実行時に組み立てられている | 固定部分だけで打ち直す（§4-2） |
| 3 | 別名で import されている | 素の名前で打ち直す（§4-1） |
| 3b | 綴りが違う（`ouptut`、`highlited`、`const`/`consts`） | 部分一致で打ち直す（§8-1） |
| 4 | 生成コードの中にある | `business-logic/` を含めて打ち直す |
| 5 | そもそも存在しない（ライブラリ側） | `node_modules` を明示的に対象にする |

5 の場合は、`rg` に `--no-ignore` を付けるか、`node_modules/@ngrx` のように直接指定する。

```bash
rg -n "createFeatureSelector" node_modules/@ngrx/store/ -g '*.d.ts'
```

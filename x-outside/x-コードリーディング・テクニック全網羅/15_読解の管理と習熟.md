# 読解の管理と習熟

探索の手法が揃っていても、時間の使い方が管理されていなければ短縮にならない。
この章は、一回の調査の進め方と、複数回にまたがる習熟の管理を扱う。

## 1. 一回の調査の型

| 段 | 時間 | やること | 成果物 |
| --- | --- | --- | --- |
| 準備 | 5分 | 問い・終了条件・仮説・反証を 4 行書く。既存資料を検索する | 作業メモの冒頭 |
| 観測 | 10分 | 動かせるなら先に動かす。Network / Redux DevTools / Angular DevTools | 通った経路の絞り込み |
| 探索 | 20〜40分 | 絞った範囲を読む。開いたファイルを `パス:行 — 分かったこと` で積む | 経路のメモ |
| 確認 | 5分 | 終了条件を満たしたか確かめる | 満たさなければ、問いを立て直す |
| 記録 | 5分 | 経路の資料にする。または既存資料へ一行足す | `ngbi-*.md` など |

準備と記録は合わせて 10 分である。これを削ると、調査が終わらないか、成果が残らない。

準備の 5 分のうち 2 分は既存資料の検索に使う（[13](13_目的別レシピ集.md) R13）。
すでに書かれていれば、残り全部が不要になる。

## 2. 深追いから抜ける

深追いは、興味と目的が一致しなくなった状態である。気付きにくいので、外形で検出する。

**検出** — 次のどれかに当たったら、深追いに入っている。

- 開始から 25 分、終了条件に近づいていない
- import を 4 段以上潜っている
- 最初に立てた問いを、メモを見ないと言えない
- 「そもそもこれは何のためにあるのか」を調べ始めた

**脱出** — 逸れた先はメモの「あとで」欄に一行で積み、元の問いへ戻る。
戻れないほど離れていたら、いったん閉じて準備からやり直す。

25 分という区切りに意味があるのは、集中が続く長さだからではなく、
それ以上続けると記憶が飽和して、戻れなくなるからである。

## 3. 打ち切る

答えが出ないまま時間が過ぎたとき、続けるか切るかを決める基準を持つ。

| 状況 | 判断 |
| --- | --- |
| 仮説を 3 つ潰したが、次の仮説が立たない | 切る。入口を変えて別の日に立て直す |
| 取り込み層の「なぜ」を 15 分探して出ない | 切る。出ないことを記録する |
| 実行時の観測で再現しない | 切る。再現手順の確定に戻る |
| 終了条件は満たしたが、確信が持てない | 切る。確信は追加の読みでは得られない。検証で得る |

最後の行が重要になる。
確信が足りないときに追加で読むと、読む量だけ増えて確信は上がらない。
代わりに、検証（ブレークポイント、ログポイント、テストを一本書く）を一つ行う。
一回の検証は、30 分の追加読解より確度が高い。

切ったことは記録に残す。「探したが出なかった」も情報である。
残さないと、次の人が同じ時間を払う。

## 4. 知識の劣化

一度きりの探索で得た知識は、参照されなければ数日で使えなくなる。
劣化の速さは、知識の種類で違う。

| 種類 | 劣化 | 対処 |
| --- | --- | --- |
| 層の構成・由来の境界 | ほぼしない | 一度覚えれば足りる |
| エイリアスと命名規約 | ほぼしない | 同上 |
| ある機能の経路 | 数週間で曖昧になる | 資料にする（[10](10_記録と資料化の型.md) §4） |
| ファイルの行番号 | 次の変更で無効 | 資料に日付を入れる。行より記号名で書く |
| 件数・規模 | 数か月で古くなる | コマンドを資料に書く（[02](02_全体地図の作り方.md) §3） |

資料に「一覧」を書かず「一覧を出すコマンド」を書くのは、この劣化の差のためである。
コマンドは古くならない。

## 5. 習熟の段階

このコードベースについて、到達点を外形で定義する。
自分がどこにいるかが分かると、次に何を読むかが決まる。

| 段 | 到達点 | 確かめ方 |
| --- | --- | --- |
| 1 | パスを見て層と由来が言える | 任意のファイルパスを見て、取り込み / 自作 / 生成のどれかを即答できる |
| 2 | 入口から目的の画面まで辿れる | URL からルート定義とコンポーネントを 3 分で特定できる |
| 3 | 値の出所を追える | 画面の任意の値について、[13](13_目的別レシピ集.md) R2 を通せる |
| 4 | 操作の行き先を追える | 任意の操作について R3 を通し、一本線の資料を書ける |
| 5 | 罠を踏まない | [12](12_時間を溶かす罠とアンチパターン.md) の 14 項目を、遭遇時に思い出せる |
| 6 | 変更の影響を見積もれる | R5 を通し、型の外の結合（DI・Action・テンプレート）も漏らさず挙げられる |

段 1 と 2 は [14_地形図](14_ClearML地形図.md) を読めば当日中に届く。
段 3 と 4 は、実際に 3〜5 本の経路を追わないと届かない。
段 5 は、踏んでから覚えるより、先に読んでおくほうが安い。

## 6. 何本読めば足りるか

このコードベースの主要な形は、次の 5 本で一巡する。
1 本 30〜60 分、合計 4 時間ほどで、以後の調査が速くなる。

| 本 | 対象 | 学べる形 |
| --- | --- | --- |
| 1 | 一覧の表示（`experiments.component.ts` → view effects → API） | Store と Effect の基本形 |
| 2 | 行クリックのハイライト（既存資料 `ngbi-01`） | Signal だけで完結する形。Store を使わない判断 |
| 3 | 実験名の変更（既存資料 `ngbi-03`、`x-sequense/01`） | 画面 → API → 一覧反映の往復 |
| 4 | 自作機能（`features/data-catalog/`） | 現代的な層構成とテストの書き方 |
| 5 | テーブル部品（`webapp-common/shared/ui-components/data/table/`） | テンプレート投影と、全画面で共有される部品 |

1・4・5 は自分で追い、2・3 は既存資料から入る。
既存資料がある経路を自分で追い直すのは、学習としては有効だが、時間短縮にはならない。

## 7. 複数人で読む

同じ箇所を二人が別々に読むのは、最も高くつく無駄である。
分担は、層で切るのではなく**経路で切る**。

層で切ると（「あなたは Effects、私は Component」）、どちらも全体が分からないまま終わる。
経路で切ると（「あなたは実験の一覧、私はモデルの一覧」）、
それぞれが縦に通るので、突き合わせたときに共通の形が見える。

突き合わせの単位は資料である。
一本線の資料（`ngbi-*.md`）は、書式が決まっているので比較できる。
比較すると、共通の形（Store の使い方、Effect の連鎖）と、
機能ごとの差（Signal で済ませている箇所）が浮かぶ。

## 8. この資料群の更新

数字は [02](02_全体地図の作り方.md) §3 のコマンドで取り直せる。
更新する契機は二つある。

- 上流を取り込んだとき（`upstream.json` の `recorded` を書き換えたとき）
- Angular か NgRx の版を上げたとき

それ以外では、[14_地形図](14_ClearML地形図.md) §8 の数字が多少ずれても判断は変わらない。
比率（取り込み 66%、生成 23%、自作 5.5%）が変わらない限り、読み方も変わらない。

# 時間を溶かす罠とアンチパターン

読み手の側の誤りではなく、コードや環境の側が誤解を招く構造になっている箇所を並べる。
すべて本リポジトリの実コードから取ってある。
先に知っていれば踏まない類のものなので、初見の前に通し読みする価値がある。

## 2. コードが実態と違って見える

### 2-1. ビルドで差し替わるファイル

`angular.json` の `fileReplacements` により、本番ビルドでは次が差し替わる。

| 開発 | 本番 | 差 |
| --- | --- | --- |
| `src/app/build-specifics/index.ts` | `index.prod.ts` | Redux DevTools の登録が消える |
| `src/environments/environment.ts` | `environment.prod.ts` | 環境設定 |

差し替えられる側のファイルには何も書かれていない。
`index.ts` を読んで「DevTools が有効だ」と判断すると、本番の話としては誤りになる。

**回避** — 機能の有無を判断する前に `angular.json` の `fileReplacements` を見る。

### 2-2. 誰からも使われていないファイル

`src/app/features/experiments/shared/experiment-shared.config.ts`（60行）は、
`EXPERIMENT_CONFIG_TOKEN` と providers 一式を定義しているが、import しているファイルが無い。

実際に使われているのは `experiments.providers.ts` のほうで、
こちらもほぼ同じ内容と、**同じ名前のトークン**を定義している。
トークン名で検索すると、死んでいる側に先に当たることがある。

**回避** — 読み始める前に参照数を数える。

```bash
rg -l -t ts "experiment-shared.config" src | grep -v "experiment-shared.config.ts"
# 出力が空 = 誰も使っていない
```

### 2-3. 登録されているが働かない仕組み

`app.config.ts` に `{provide: RouteReuseStrategy, useClass: CustomReuseStrategy}` がある。
この実装は `route.data.reuse` が真のときだけ画面の状態を保持するが、
`data: {reuse: true}` を持つルートはリポジトリ内に一つも無い。

```bash
rg -n -t ts "reuse: true" src
# 出力なし
```

「画面を戻ったときに状態が保持される仕組みがある」と読むと誤る。
仕組みは在るが、この版では発動しない。

**回避** — 条件で分岐する仕組みを見たら、その条件を満たす記述が実在するかを検索で確かめる。

### 2-4. Reducer に書かれていない永続化

状態の localStorage への保存は meta-reducer が行う。
Reducer をいくら読んでも保存処理は出てこない。

キーは六つある（`_saved_state_`、`_saved_experiment_state_`、`_saved_models_state_`、
`_saved_compare_state_`、`_saved_endpoints_state_`、`_saved_pipeline_state_`）。
仕掛け場所は `core/core.config.ts` と各 `*.providers.ts` である。

`experiments.providers.ts` の meta-reducer は、初回だけ localStorage の内容を
`merge` で現在の state に重ねる。つまり**初期値が上書きされる**。

**回避** — 「初期値がおかしい」調査では、DevTools の Application タブで
該当キーを消してから再現する。消して直るなら永続化が原因である。

### 2-5. 循環依存

35 件の循環がある。典型は「Action ファイルが Component を import し、
その Component が Action を import する」形である。

```bash
npx madge --ts-config tsconfig.json --extensions ts --circular src/app
```

循環していると、モジュールの評価順によっては、
import した値が評価時点でまだ `undefined` になる。
これは「定義してあるのに undefined」という症状として現れる。

**回避** — `undefined` の原因が分からないときは、循環の一覧を先に見る。
その対に入っていれば、評価順を疑う。

### 2-6. 型注釈が実態を表していない

`tsconfig.json` は `strict: false` である。
加えて `: any` が 683 箇所、`as any` が 55 箇所ある。

生成された API クライアントも `Observable<any>` を返す箇所が多い
（`tasksGetAllEx` の戻り値も `Observable<any>` である）。
型から実際のレスポンス形状は読めない。

**回避** — `any` に出会ったら型を追うのをやめ、実行時の値を見る。
Network タブのレスポンス、または `ng.getComponent($0)` の展開が速い。
厳しい検査は別構成で走らせる。

```bash
pnpm run web:typecheck:strict
```

## 3. 名前とコメントが実態と違う

### 3-1. ディレクトリ名から役割を誤る

| 名前 | 想像する役割 | 実際 |
| --- | --- | --- |
| `business-logic/` | 業務ロジック | API クライアントと生成モデル（607 中 584 が生成物） |
| `webapp-common/` | 共通部品 | 取り込み元の本体そのもの（全体の 66%） |
| `features/` | 機能の実装 | 上書きのための差し込み口。103 ファイル中 25 が 15 行未満 |
| `shared/` | 共有部品 | `webapp-common` から `~/shared` として参照される差し替え層 |

**回避** — 名前ではなく行数とファイル数で役割を決める（[02](02_全体地図の作り方.md) §3）。

### 3-2. 推測で書かれたコメント

`webapp-common/core/router-reuse-strategy.ts` の JSDoc には
"I believe the boolean is indicating to a controller whether or not to fire this.store" とある。
書き手自身が推測で書いており、仕様ではない。

一方、`app.config.ts` の `provideHttpClient(withInterceptorsFromDi())` に付いた注記は正確である。

**回避** — コメントの信用度は書き手で分ける。
自作層（`features/` `core/` `shared/` `app.config.ts` `scripts/`）は高く、
取り込み層は確認するまで信用しない（[09](09_履歴とフォーク差分から読む.md) §7）。

## 4. 検索が当たらない・誤って当たる

### 4-1. テンプレートリテラルで組まれた識別子

Redux DevTools に `[select model] set models` と表示されても、
この文字列はソース上に存在しない。`createAction` の引数が
`` `${SELECT_MODEL_PREFIX} set models` `` と書かれているためである。
この形が 23 箇所ある（`SELECT_MODEL_PREFIX` が 21 件、`USERS_PREFIX` が 2 件）。

**回避** — 角括弧の部分を捨て、後半だけで検索する。

```bash
rg -n -t ts "set models" src
```

### 4-2. 同名で値が違う定数

| 定数名 | 定義場所 | 値 |
| --- | --- | --- |
| `EXPERIMENTS_INFO_PREFIX` | `common-experiments-menu.actions.ts:8` | `'[EXPERIMENTS INFO] '` |
| `EXPERIMENTS_INFO_PREFIX` | `common-experiments-info.actions.ts:41` | `'[Experiments Info ]'` |
| `MODELS_PREFIX` | `models-info.actions.ts:10` | `'MODELS_INFO_'` |
| `MODELS_PREFIX` | `models-view.actions.ts:12` | `'MODELS_'` |
| `MODELS_PREFIX` | `models-menu.actions.ts:5` | `'[MODELS_MENU] '` |

定数名で当たりを付けると、別の Action 系統のファイルに着地する。

**回避** — 定数名ではなく値で検索する。

```bash
rg -n -t ts "'\[Experiments Info \]'" src
```

### 4-3. 同名ファイルで、別の層に着地する

`models.ts` 17 個、`login.service.ts` 3 個、`tasks.service.ts` 2 個。
これが罠になるのは、間違ったほうを開いたときに**間違えたことに気付かない**からである。
どちらも構文として正しく、内容も似ているので、読み進めてから食い違いに気付くことになる。

`tasks.service.ts` の 2 個は特に紛らわしい。
`business-logic/api-services/tasks.service.ts`（2,331 行、生成された API クライアント）と、
`webapp-common/tasks/` 配下のものは、役割がまったく違う。

**回避** — 開いた直後に、パスの先頭で層を確認する習慣を付ける。
検索の手順は [04_静的探索](04_静的探索の道具と手順.md) §3。

### 4-4. 別名で import された参照

Reducer は Action を名前空間付きの別名で参照する。

```ts
on(actions.setExperimentLog, (state, action) => ...)
```

`on(setExperimentLog` では当たらない。

**回避** — 修飾を付けず、素の名前で検索する。
一回で定義・Reducer・Effect・dispatch 元がまとめて出る。

```bash
rg -n -t ts "setExperimentLog" src
```

### 4-5. 綴りのゆれと誤り

正しい綴りで検索しても当たらない箇所がある。

| 綴り | 実例 | 正しい綴りでの検索結果 |
| --- | --- | --- |
| `ouptut` | `experiments/containers/experiment-ouptut/`（両層に存在） | `output` では当たらない |
| `highlited` | 一覧のハイライト状態（11 箇所）。`highlighted` も 33 箇所ある | どちらか片方では半分しか出ない |
| `const` / `consts` / `constants` | `experiments.const.ts` / `experiments.consts.ts` / `experiments-compare.constants.ts` | 一つの綴りでは 3 分の 1 しか出ない |
| 単数 / 複数 | `webapp-common/experiments/experiment.consts.ts` と `features/experiments/experiments.consts.ts` | 同上 |

**回避** — 当たらないときは部分一致に落とす。

```bash
rg -n -t ts "highli" src           # 両方の綴り
find src -type d -name "*ou*put*"  # ouptut と output の両方
find src -name "experiment*.const*.ts"
```

### 4-6. 画面の語と API の語が違う

画面の「Experiment」は、データ上は `task` である。
`business-logic/api-services/` に `experiments.service.ts` は存在せず、
`webapp-common/experiments/` の Effects はすべて `ApiTasksService` を注入している。

同様に `events.*` API はスカラー指標・プロット・ログ・デバッグ画像を指し、UI のイベントではない。

**回避** — 検索語を決める前に用語の対応表を引く。
[14_地形図](14_ClearML地形図.md) §5 に対応表がある。
一次情報は `src/app/shared/constants/non-common-consts.ts` の `EntityTypeEnum` である。

## 6. 環境の罠

### 6-1. 検索のノイズ

ルート直下に `node_modules`（437 パッケージ）、`dist`、`build`、`.angular`、
`.venv`、`reports`、`test-results` がある。

`.vscode/settings.json` の `search.exclude` でエディタ側は除外済みだが、
シェルから `grep -r` を打つと除外は効かない。

**回避** — `rg` を使う。`.gitignore` を既定で尊重する。対象は `src` に限る。

### 6-2. `sg` は `ast-grep` ではない

この環境に `ast-grep` は入っていない。
`/usr/bin/sg` は存在するが、これは Linux の `setgroups` である。
`ast-grep` のつもりで `sg` を打つと別のコマンドが走る。

入っていない道具は他に `jq`・`fd`・`fzf`・`ctags`・`cscope`・`semgrep` がある。
入っているのは `rg`・`madge`・`tree`・`git`・`node`・`pnpm` である。

### 6-3. バックエンドのポート競合

`../001-learn-ClearML` とポート 8008/8080/8081 を共有している。同時起動はできない。
切り替えるときは、先にもう一方を `backend:down` する。
`docker volume prune` は停止中の別プロジェクトのボリュームを消すので実行しない。

画面が組み上がらないときは、コードを読む前に確かめる。

```bash
pnpm run backend:status
```

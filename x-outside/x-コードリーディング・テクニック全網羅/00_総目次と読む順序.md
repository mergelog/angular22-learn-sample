# コードリーディング手法 総目次

このフォルダは、本リポジトリ（ClearML Web を fork した Angular アプリと、その周辺の Python 実装）を
読むための手法をカテゴリごとに分けて置いたものである。

目的は一つに絞ってある。**同じ問いに答えるまでの時間を短くすること**である。
コードを網羅的に理解することではない。網羅は目的にならない。src/app だけで TypeScript 118,517 行あり、
全部読む経路には終わりがない。必要なのは「この問いには、この経路で、この深さまで読めば答えが出る」という
判断であり、この資料群はその判断材料を並べている。

## 1. なぜ手法で速くなるのか

読解時間は、次の三つの積で決まる。

| 要素 | 内容 | 短くする手法 |
| --- | --- | --- |
| 読む量 | 目的に対して何行開いたか | 02（地図）・03（戦略）・04（探索）で、開くファイルを絞る |
| 再読の回数 | 同じ箇所を何度開き直したか | 10（記録）で外部記憶に出す。14（地形図）で毎回の再調査をなくす |
| 手戻り | 誤った理解のまま進んで戻った回数 | 05（実行時観測）で仮説を早く反証する。12（罠）で既知の誤読を避ける |

三つのうち、初学者がいちばん取りこぼすのは**再読**である。
一度たどった経路を記録せずに閉じると、二週間後に同じ 40 分を払う。
時間短縮の効果が最も大きいのは、探索の速さではなく記録の習慣である。

## 4. 使い方の三原則

**一度の調査で一つの問いだけ答える。** 「ついでにあれも」を許すと、経路が枝分かれして記録が残らない。
枝は別の問いとしてメモに積み、いまの問いを閉じてから取る。

**読む前に、答えの形を決める。** 「どのファイルの何行目に何が書いてあれば答えになるか」を先に書く。
形が決まっていない調査は、いつまでも終わらない。

**閉じる前に、たどった経路を残す。** 残す先は [10_記録と資料化の型](10_記録と資料化の型.md) に定めてある。
残さなかった調査は、次に同じ時間を払う。

### 設計上の注意

  親子間で普通に値を渡すだけなら input(), output(), model() が基本
  
  viewChild() は、「子コンポーネントそのものを直接触る必要がある」ときに使います。
  
  例えば
    + フォーカスする
    + スクロールする
    + ダイアログを開く
    + 子の公開メソッドを呼ぶ
    + DOMを参照する
  単純な状態受け渡しを全部 viewChild() でやると、親子が強く結合しすぎます。

  contentChild: 親コンポーネント側から <ng-content>（コンテンツ挿入枠）を経由して、自分の内側に注入（プロジェクション）された要素や子コンポーネン  トを操作したいとき
  にそれぞれ使う
  
  ```

    imports: [Sample22OkPanel],
    `
      <app-sample-22-ok-panel /> // 👈ここにあるので
      <p>viewChild: {{ viewPanel() ? '取れた(OK)' : '取れない' }}</p>
      <p>contentChild: {{ contentPanel() ? '取れた' : '取れない!!' }}</p>

  @Component({
    selector: 'app-sample-22-ng-frame',
    template: `
      <ng-content /> // Sample22NgPanel　はここにはない。（親が持っている<app-sample-22-ng-frame><app-sample-22-ng-panel /></  app-sample-22-ng-frame>）
      <p>viewChild: {{ viewPanel() ? '取れた' : '取れない' }}</p>
  ```

## ▼ 属性バインディング

```ts
// ↓ クラスだと
value = 'abc';

// ↓ htmlだと

<p [attr.foo-bar]="value">
  こんにちは
</p>

// ↓ 普通のhtmlだと

<p foo-bar="abc">
  こんにちは
</p>

// ↓　使う

const element = document.querySelector('[foo-bar="abc"]');
console.log(element?.textContent);

```

* `card-footer` はただの属性。Angularでは `ng-content select="[card-footer]"` で拾うための「投影先マーカー」として使える。
* `[card-footer]` は CSS の属性セレクター。`card-footer` 属性を持つ要素にマッチする。
* Angularと無関係でも `<p foo-bar>` のような独自属性は付けられるが、通常の独自データなら `data-foo-bar` が標準的。
* Angularの `[attr.xxx]="value"` は、HTML属性そのものを動的に設定する書き方。`value = 'abc'` なら `foo-bar="abc"` になる。
* 実務で `attr.` が嬉しいのは、`aria-*`、`data-*`、`colspan`、SVG属性などをAngularの値から動的に変えたいとき。

```ts
js: const el = document.querySelector('[data-status="warning"]');
html: <p data-status="warning">注意</p>
css: [data-status="warning"] { font-weight: bold; }
```

Angularの状態に応じて、アクセシビリティ情報や識別用データ、表の結合数などをDOM属性として動的に変えたいときに便利。

## ▼　▶️ Store; NgRX/RxJS

### - {dispatch: false} ※createEffect内  

action として Store に dispatch させない指定

型の中身まで追う必要はありません。実際に使うときは次の2つだけで足ります。

effect が action を返さず、URLの書き換えなどの副作用だけを行うときは {dispatch: false} を付ける  
付け忘れると Type '...' is not assignable to type 'Action<string>' のような型エラーが出る。このエラーが出たら、まず {dispatch: false} の付け忘れを疑う

### > catchError()

[L00_初期etc/32_catchError.md](./L00_初期etc/32_catchError.md)  

catchError は RxJS で、Observable の途中で発生したエラーを捕まえて、別の Observable に差し替えるためのオペレータ  
try catchと同じ考え。  
  * `catchError(() => of(...))`：エラー処理。エラーを正常値に置き換えて、その値を流す。
  * `catchError(() => EMPTY)`：もみ消し。エラーを飲み込み、何も流さずその処理を終了する。
  * `catchError(error => throwError(() => error))`：エラーを捕まえるが、処理せず再び上位へ投げる。
  * `catchError` の位置：`switchMap` の内側ならその1回の処理だけ失敗、外側なら Observable 全体が終了しやすい。

### withLatestFrom concatLatstForm 違い

  普通のRxJSなら withLatestFrom。EffectでStoreの値を足すなら concatLatestFrom。
  
  ```
  withLatestFrom → 相手の Observable を先に購読して、最新値を待っている
  concatLatestFrom → 元の値が流れてきた瞬間に、必要な Observable を取りに行く
  ```
  
  concatLatestFrom の大きな利点は、左側の値を使って「どの selector を読むか」を決められること

  |                   | `withLatestFrom` | `concatLatestFrom`   |
  | ----------------- | ---------------- | -------------------- |
  | 所属                | RxJS             | `@ngrx/operators`    |
  | 相手を購読するタイミング      | 先に購読             | 元データが来てから            |
  | 左側の値を使える          | 基本やりにくい          | `action => ...` と使える |
  | NgRx Effects      | 使える              | **こちらを優先**           |
  | 普通の Observable 同士 | **よく使う**         | NgRx向け               |

### take()、first() の違い


first() がエラーになる条件: 値が1件も来ないまま、first() から見て Observable が complete した

```ts
// 値が来る前にコンポーネントが destroy されたら、takeUntilDestroyed() が購読を解除
source$.pipe(
  first(),
  takeUntilDestroyed()
)
// この場合、first() に「completeしたよ」という通知が来るわけではなく、単に unsubscribe されます。
// なので通常、first() の EmptyError は出ません
```

一方、順番が逆だと

```ts
/*
source$
   ↓
takeUntilDestroyed()
   ↓ destroyされたので complete
first()
   ↓
「1個も来てないのにcompleteした！」
   ↓
EmptyError
*/
source$.pipe(
  takeUntilDestroyed(),
  first()
)
```

となり得ます。

| 項目                         | `take(1)`    | `first()`    |
| -------------------------- | ------------ | ------------ |
| 最初の1件を取得                   | ○            | ○            |
| 1件取ったら complete            | ○            | ○            |
| 1件も来ずに元Observableがcomplete | そのままcomplete | `EmptyError` |
| 条件指定                       | ×            | ○            |
| デフォルト値                     | ×            | ○            |

### debounceTime と debounce

debounceTime は待ち時間が固定です。たとえば 300ms なら、最後の入力から300ms何も来なければ、その値を流します。検索入力でよく使います。

debounce は値ごとに待ち時間を変えられます。例：1文字なら1秒、3文字以上なら300ms待つ、という制御ができます。通常は debounceTime を使います。

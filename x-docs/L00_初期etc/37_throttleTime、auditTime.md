---


| Operator            | いつ出す？               | 500ms内に A→B→C が来たら | 向いている用途            | ユースケース例                                       |
| ------------------- | ------------------- | -----------------: | ------------------ | --------------------------------------------- |
| `debounceTime(500)` | 入力が500ms止まったら出す     |                `C` | 入力完了を待ちたい処理        | 検索ボックス、入力補完、フォーム入力後の自動保存、API検索                |
| `throttleTime(500)` | 最初を即出して、500ms無視     |                `A` | 短時間の連続実行を抑えたい処理    | 保存ボタン連打防止、送信ボタン、多重クリック防止、スクロールイベント抑制          |
| `auditTime(500)`    | 500ms待って、その時点の最新を出す |                `C` | 動き続ける値を一定間隔で取りたい処理 | スクロール位置、マウス位置、ウィンドウサイズ変更、ドラッグ中の座標、リアルタイム値の間引き |

---

並べると、こうです。

| Operator            | いつ出す？               | 500ms内に A→B→C が来たら | 向いている用途    |
| ------------------- | ------------------- | ------------------ | ---------- |
| `debounceTime(500)` | 入力が500ms止まったら出す     | `C`                | 検索入力       |
| `throttleTime(500)` | 最初を即出して、500ms無視     | `A`                | 連打防止       |
| `auditTime(500)`    | 500ms待って、その時点の最新を出す | `C`                | スクロール・位置情報 |

時間で見るとこうです。

```text
入力
0ms     A
100ms   B
200ms   C
800ms   D
```

`debounceTime(500)`

```text
A B C -------- C
                ↑
        最後の入力から500ms後

D -------- D
```

結果:

```text
C, D
```

`throttleTime(500)`

```text
A
↑ 即出す

  B C
  ↑ 無視

800ms D
      ↑ 即出す
```

結果:

```text
A, D
```

`auditTime(500)`

```text
A B C ---- C
          ↑
   最初のAから500ms後に
   その時点の最新Cを出す

D ---- D
```

結果:

```text
C, D
```

特に混同しやすいのが `debounceTime` と `auditTime` です。

`debounceTime` は「入力が止まるまで待つ」。

```text
入力されるたびに500msタイマーをリセット
```

なので、入力がずっと続けば、ずっと出ません。

一方 `auditTime` は「入力が続いていても、500ms経ったら最新値を出す」。

```text
500msごとに最新値を拾う
```

という感覚です。

覚え方はこれで十分です。

```text
debounceTime = 止まったら最後
throttleTime = 最初を即採用
auditTime    = 一定時間後に最後
```

検索欄なら `debounceTime`、ボタン連打なら `throttleTime`、スクロールやマウス移動のように「動き続けても定期的に最新値が欲しい」なら `auditTime`、という使い分けが分かりやすいです。


---

かなり似ていますが、違いは「時間帯の最初を採るか、最後を採るか」です。

| Operator            | 500msの間に何度も来たら             | イメージ  |
| ------------------- | -------------------------- | ----- |
| `throttleTime(500)` | **最初の1件を即採用**して、その後500ms無視 | 最初を採る |
| `auditTime(500)`    | 500ms待って、**最後の1件を採用**      | 最後を採る |

たとえば入力がこう来たとします。

```text
0ms     A
100ms   B
200ms   C
800ms   D
```

`throttleTime(500)` は、

```text
A ---------------- D
↑即出す              ↑即出す
 B,Cは無視
```

結果：

```text
A, D
```

一方、`auditTime(500)` は、

```text
A B C ----→ C
             ↑
        500ms後に
        最新値を出す

800ms D ----→ D
```

結果：

```text
C, D
```

コードならこうです。

```ts
search$.pipe(
  throttleTime(500)
);
```

これは「一度実行したら500msは連打を無視」。たとえば保存ボタン、スクロールイベント、クリック連打防止などです。

```ts
search$.pipe(
  auditTime(500)
);
```

これは「500msごとに、その期間の最新状態だけ欲しい」。たとえばスクロール位置やマウス位置など、頻繁に変化する値を間引いて取得するときです。

一言で覚えるなら、

**`throttleTime` = 最初を即採用 → しばらく無視**
**`auditTime` = しばらく待つ → 最後を採用**

なお、検索入力ならこの2つより `debounceTime()` がよく使われます。`debounceTime()` との違いまで並べると、この3つはかなり綺麗に整理できます。

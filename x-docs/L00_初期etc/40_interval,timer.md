この2つは、どちらも「時間を起点に Observable を流す関数」です。違いは「最初の通知をいつ出すか」です。

| 関数                  | 動き              | 例                      | 主な用途        |
| ------------------- | --------------- | ---------------------- | ----------- |
| `interval(1000)`    | 1秒待ってから、その後1秒ごと | `1秒後 → 0 → 1 → 2...`   | 一定間隔の繰り返し処理 |
| `timer(1000)`       | 1秒後に1回だけ        | `1秒後 → 0 → 完了`         | 遅延実行        |
| `timer(1000, 3000)` | 1秒後に開始し、その後3秒ごと | `1秒後 → 0 → 3秒後 → 1...` | 開始を遅らせた定期処理 |
| `timer(0, 5000)`    | ほぼ即時に1回、その後5秒ごと | `0 → 5秒後 → 1...`       | APIポーリング    |

特に学習上はこれで十分です。

```ts
interval(5000)
```

は、

```text
5秒待つ
↓
実行
↓
5秒待つ
↓
実行
```

一方、

```ts
timer(0, 5000)
```

は、

```text
すぐ実行
↓
5秒待つ
↓
実行
↓
5秒待つ
↓
実行
```

なので、実務のAPIポーリングでは `timer(0, N)` がかなり分かりやすいです。

```ts
timer(0, 5000).pipe(
  switchMap(() => this.api.getExperiments())
)
```

これは「画面を開いたらすぐ取得、その後5秒ごとに再取得」です。

学習表の

> `interval()` / `timer()` | 周期通知 / 遅延 + 周期通知 | `timer(0, N)` は「即時 + 定期」。ポーリングの起点

という説明は、ほぼそのままで適切です。より正確にするなら、`timer()` は「遅延 + 周期」だけでなく、**遅延して1回だけ通知する用途もある**、という点を足しておくとよいです。 ([rxjs.dev][1])

[1]: https://rxjs.dev/api/index/function/interval "RxJS"

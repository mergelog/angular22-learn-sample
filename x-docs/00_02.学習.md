
## Signal

````ts

// === 基本

// 設定
readonly count = signal(0);

// 読む
this.count()

// 変更
this.count.set(10);

// 今の値を使って、新しい値を作る
this.count.update(value => value + 1);

// === computed
readonly price = signal(1000);
readonly quantity = signal(2);
/*
quantityが変わった
        ↓
totalはquantity()を使っている
        ↓
totalも再計算が必要

と依存関係を追跡します。computed() は依存するSignalから派生値を作るための、読み取り専用Signalです。
*/
readonly total = computed(
  () => this.price() * this.quantity()
);

// === effect
readonly count = signal(0);
/*
現在のAngular公式は effect() をかなり限定的に使うよう勧めていて、単なる「値Aが変わったら値Bを更新」という用途では、まず computed() などを検討する方針です。effect() はログ、localStorage、外部UIライブラリなど、Signal世界の外側に副作用を起こす場面が主用途です。

派生状態には computed() を優先し、Signal間の状態伝播のために effect() を使うのは避ける
*/
constructor() {
  effect(() => {
    console.log('count:', this.count());
  });
}

// === オブジェクト内部変更は検知しない
readonly experiments = signal<Experiment[]>([]);

// 検知しない
this.experiments().push(newExperiment);
// 検知する
this.experiments.update(current => [
  ...current,
  newExperiment
]);

// === デフォルトの等価比較は Object.is()
// NG（検知されない）
this.data().user.name = 'Suzuki';
// OK
this.data.update(data => ({
  ...data,
  user: {
    ...data.user,
    name: 'Suzuki'
  }
}));

// === 

````

## Signal: input() output() model()

- 親子関係の結論
input()  = 親 → 子 // 宣言は子
output() = 子 → 親 // 宣言は親
model()  = 親 ⇄ 子
そして input() と model() は Signal 系です。
そして大抵は 左が子、右が親 の配置の感じとなる

```ts

// === 1分目：input() は「親から受け取るSignal」
/*
  親から値を受け取る
        ↓
  子ではSignalとして扱う
*/
// 子が待ち受ける
readonly message = input<string>('');
readonly message = input.required<string>(); // 親は必ず message を渡してください

// 子が以下で出力
this.message()
<p>{{ message() }}</p>

// 親は・・・以下のように渡す
<app-child [message]="title()" />

// === 2分目：output() は「子からイベントを出す」
/*
子 selected.emit(123)
      ↓
親 (selected)
      ↓
onSelected(123)
*/
// 子が配信する準備
readonly selected = output<number>(); // output() 自体は「状態を持つSignal」ではない（signal() や input() は「値を持つ」。）
// 配信
this.selected.emit(123);

// 親は・・・
<app-child
  (selected)="onSelected($event)"
/>

// === 3〜4分目：model() は双方向
/*
  値を持つ
  +
  親へ変更通知もできる
*/
// 子で宣言
readonly count = model(0);

// 子が読む
this.count()
// 子が変更もできる
this.count.set(10);

// 親は・・・
readonly count = signal(0); // 同名の変数用意して
<app-child [(count)]="count" /> // と書ける

// 落とし穴
readonly title = input.required<string>(); // Signalなので
this.title() // こう読む

// 一方

readonly saved = output<void>(); // はSignalではないので、
this.saved.emit(); // としなければならない
```

- 左が子、右が親
  ```
  <!--
    <app-inner-a
      [message]="messageForChild()"          // [message]は子が宣言しているinput.required、messageForChild()は親が宣言したSignal
      [(count)]="count"                      // [(count)]は子のcount、"count"は親のcount
      (messageSent)="receiveMessage($event)" // (messageSent)は子が宣言しているoutput、親が持つメソッドreceiveMessage($event)
    />

    [子input]="親signal"
    (子output)="親method"
  -->

    [子input]="親signal"
    (子output)="親method"

    // --- sample-06-template-outlet-basic
    // こういう場合もある
    // 子のinput に greeting（つまり<ng-template #greeting>）を渡して、子自体はここで表示（ややこしい）
    <app-sample-06-template-host [content]="greeting" />
    <ng-template #greeting>
     　<p class="greeting">親が渡したメッセージです。</p>
    </ng-template>

  ```

## Signal: viewChild

```ts
@Component({
  imports: [ChildComponent],

しておけば

readonly child = viewChild(ChildComponent);

だけで

<app-child /> と書ける（readonly child なくても書けると思う）

但し・・・

■設計上の注意

親子間で普通に値を渡すだけなら input(), output(), model() が基本

viewChild() は、
「子コンポーネントそのものを直接触る必要がある」
ときに使います。

例えば
  + フォーカスする
  + スクロールする
  + ダイアログを開く
  + 子の公開メソッドを呼ぶ
  + DOMを参照する
単純な状態受け渡しを全部 viewChild() でやると、親子が強く結合しすぎます。

// === 8〜10分：DOM要素そのものも取れる

// 子のhtml
<input #searchBox />

// 親は・・
  readonly searchBox =
    viewChild<ElementRef<HTMLInputElement>>('searchBox');
    で取れる。そして
  this.searchBox()?.nativeElement.focus();
    とできる（公式ドキュメントでもサポート）

■ 重要な落とし穴：DOMを何でも直接いじらない
this.searchBox()!.nativeElement.style.color = 'red';
のような直接DOM操作は、必要な場面以外では増やさない方がいいです。

単なる表示変更なら、
<input [class.error]="hasError()" />
<input [disabled]="disabled()" />
などAngularのテンプレートバインディングを使う方が基本です。

viewChild<ElementRef> は
- focus()
- scrollIntoView()
- サイズ取得
- 外部UIライブラリ連携
DOMそのものに触れる必要がある場合

に使うイメージです。

// === 10〜12分：viewChildren() は複数版

// 子

<app-child />
<app-child />

// 親は・・
readonly children = viewChildren(ChildComponent);

  Signal<readonly ChildComponent[]>

  this.children()

  readonly childCount = computed(
    () => this.children().length

// === 12〜13分：昔の @ViewChild との違い
```

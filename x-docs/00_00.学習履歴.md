- dataset登録

> 実運用の場合もそういうコマンドから開始になりますか? 知識として

はい、初回登録や単発の作業では、このCLIコマンドから始めることもあります。ClearMLはDatasetの作成方法としてCLIとPython SDKの両方を提供しています。ClearML Data
一般的な企業の定常運用では、毎回担当者がコマンドを打つより、データ取得・検証・Dataset登録をプログラムにして定期実行する形が多いです。これは運用上の推奨で、ClearMLのSDKはその処理をコードに組み込めます。Dataset SDK、実行の自動化
今は仕組みを理解するため、作成 → ファイル追加 → アップロード・確定 を一操作ずつ手で体験する段階です。先ほどの作成コマンドは、まだ実行せずに保留していて大丈夫です。

- task作成
- queueに追加

はい。学習用なら、**同じPCで動いている ClearML Fileserver（`http://localhost:8081`）を擬似的な共有保存先**として使えます。外部のストレージを用意する必要はありません。ただし、今のモデル URL は `file:///tmp/...` なので、まず Fileserver に保存されるようにして再実行します。

順序は次が分かりやすいです。

1. **保存**：再実行後、モデル URL が Fileserver を指すことを確認する。
2. **学習済みモデルの再利用**：別プロセスからモデルを取得し、推論できることを確認する。
3. **合格基準を決める**：不良品の見逃しを何件まで許容するかなどを決め、評価ゲートに反映する。
4. **合格モデルを staging に昇格**する。

今回の保存漏れには心当たりがあります。学習コードは `Task.init(output_uri=...)` を指定していますが、[Pipeline 側のコード](/home/mtrysd/work_2026/000-learn-ClearML-pro/ml/pipeline/step_cli.py:72)には「Agent 上ではそれだけでは既存 Task の保存先が更新されない」という対策が既にあります。次の具体的な作業は、同じ対策が[学習 Task 側](/home/mtrysd/work_2026/000-learn-ClearML-pro/ml/semiconductor_quality/clearml_tracking.py:304)にも必要か確認し、保存から再取得まで通すことです。

## ▼ AIと会話した

今やったのはまさに「1回の実験」です。

ClearMLでは、その1回の実行を基本的に `Task` として記録します。

今回だと、

```text
Dataset v1.0.0を使う
↓
train / validation / testに分ける
↓
RandomForestで学習
↓
accuracy / precision / recall / F1を出す
↓
ModelとArtifactを保存する
```

この一連が1つの実験です。
そしてClearML上では、

```text
実験 = Task
```

とほぼ考えて大丈夫です。

厳密にはTaskは実験以外にも使われます。さっき見たDataset用の `Data Processing Task` もTaskでした。

なので整理すると、

```text
Task
├─ Dataset作成・加工のTask
├─ 機械学習のTraining Task ← 今やったもの
├─ 推論Task
├─ PipelineのStep
└─ その他の処理
```

です。

今回作ったTaskは、その中の「Training Task」です。

これから例えば、

```text
1回目
Dataset v1.0.0
max_depth = None

2回目
Dataset v1.0.0
max_depth = 6
```

とすれば、これは「条件を変えた別の実験」になります。

つまり、

```text
Experiment 1 → Task A
Experiment 2 → Task B
```

という関係です。

そしてClearMLの強みは、この複数の実験をあとで比較できることです。

「どのDatasetを使ったか」
「パラメータは何だったか」
「精度はいくつだったか」
「どのModelができたか」

をTask単位で並べて比較できます。

今回の1回目は、いわば **baseline experiment** です。これを基準に、次から条件を1つずつ変えて実験していく流れになります。

## ▼ AIとの会話: 次

今やったのは「最初の基準実験」を1本通した段階です。

次の流れはかなり自然で、

1. 今回のTaskの中身をClearML Webで確認する
2. `max_depth`など1つだけ条件を変えて2回目を実行する
3. 1回目と2回目をCOMPAREする
4. Dataset Versionを`1.0.0`→`2.0.0`に変えて再実験する
5. 「パラメータ変更」と「データ変更」で結果がどう変わるかを見る
6. その後にQueue / AgentでRemote Executionへ進む

という順番です。

つまり、

```text
基準実験
↓
条件変更
↓
比較
↓
Dataset変更
↓
比較
↓
Remote Execution
```

です。

今の段階では、まだ「ClearMLで実験を記録できた」だけです。これから「ClearMLで実験を比較・再現・再実行する」に進みます。ここまで行くと、ClearMLを使う意味がかなり見えてきます。

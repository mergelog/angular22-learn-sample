## ▼ AIと会話した

今やったのはまさに「1回の実験」です。

ClearMLでは、その1回の実行を基本的に `Task` として記録します。

今回だと、

```text
Dataset v1.0.0を使う
↓
train / validation / testに分ける
↓
RandomForestで学習
↓
accuracy / precision / recall / F1を出す
↓
ModelとArtifactを保存する
```

この一連が1つの実験です。
そしてClearML上では、

```text
実験 = Task
```

とほぼ考えて大丈夫です。

厳密にはTaskは実験以外にも使われます。さっき見たDataset用の `Data Processing Task` もTaskでした。

なので整理すると、

```text
Task
├─ Dataset作成・加工のTask
├─ 機械学習のTraining Task ← 今やったもの
├─ 推論Task
├─ PipelineのStep
└─ その他の処理
```

です。

今回作ったTaskは、その中の「Training Task」です。

これから例えば、

```text
1回目
Dataset v1.0.0
max_depth = None

2回目
Dataset v1.0.0
max_depth = 6
```

とすれば、これは「条件を変えた別の実験」になります。

つまり、

```text
Experiment 1 → Task A
Experiment 2 → Task B
```

という関係です。

そしてClearMLの強みは、この複数の実験をあとで比較できることです。

「どのDatasetを使ったか」
「パラメータは何だったか」
「精度はいくつだったか」
「どのModelができたか」

をTask単位で並べて比較できます。

今回の1回目は、いわば **baseline experiment** です。これを基準に、次から条件を1つずつ変えて実験していく流れになります。

## ▼ AIとの会話: 次

今やったのは「最初の基準実験」を1本通した段階です。

次の流れはかなり自然で、

1. 今回のTaskの中身をClearML Webで確認する
2. `max_depth`など1つだけ条件を変えて2回目を実行する
3. 1回目と2回目をCOMPAREする
4. Dataset Versionを`1.0.0`→`2.0.0`に変えて再実験する
5. 「パラメータ変更」と「データ変更」で結果がどう変わるかを見る
6. その後にQueue / AgentでRemote Executionへ進む

という順番です。

つまり、

```text
基準実験
↓
条件変更
↓
比較
↓
Dataset変更
↓
比較
↓
Remote Execution
```

です。

今の段階では、まだ「ClearMLで実験を記録できた」だけです。これから「ClearMLで実験を比較・再現・再実行する」に進みます。ここまで行くと、ClearMLを使う意味がかなり見えてきます。

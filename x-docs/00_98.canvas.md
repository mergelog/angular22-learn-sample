> madgeって何が嬉しいか。だからどうした感がすごい

その感覚は正しいと思います。1500ファイルの全体図を描くと線が絡まった塊になり、見ても分かることはほとんどありません。しかも Angular の import は model・actions・utils・service への参照が大半なので、画面の構造は図に出てきません。

madgeの依存図は眺めて理解するためのものではありません。調べたいことを決めてから絞り込んで使います。役に立つのは次のような場面です。

循環依存を増やさないようにする: madge --circular をCIやlintに組み込み、件数が増えたら失敗させます。一番実用的な使い方です。
影響範囲を調べる: 変更前に --depends で「このファイルを誰が使っているか」を確認します。
図にするなら範囲を絞る:
循環している部分だけを描く: madge --circular --image cycles.svg ...
1ファイルを起点にして model/actions などを除外する: --exclude '(model|actions|\.spec)'
画面やコンポーネントの構造を理解したいなら、madgeは向いていません。ngmaze（テンプレート上の親子関係）や ngbi（処理の流れの追跡）の方が合っています。

> Enterで入力キャンセルされてしまう

JavaScriptには、IMEの入力状態を認識するためのイベントが用意されています。

compositionstart: IMEの入力（変換）が始まったとき

compositionend: IMEの変換が確定したとき

正常に制御されているフォームでは、compositionendが完了するまでEnterキーによる送信処理をブロック（スキップ）するように実装されています。

# Angular 22 / RxJS / NgRx / Signal 逆引き辞書

これは「何を選ぶか」の入口です。同じ欄に名前があっても完全な代替ではありません。特に Signal は**現在値**、RxJS は**時間軸上の通知**、NgRx は**Action を起点にした共有状態の管理**を扱います。

| 大分類 | やりたいこと | 判断・注意 | RxJS | NgRx | Signal |
| --- | --- | --- | --- | --- | --- |
| 状態 | 現在値を保持したい | 局所的な UI 状態ならまずこれ | `BehaviorSubject`（必要なときだけ） | `Store` / SignalStore | `signal()` |
| 状態 | アプリ全体で共有したい | 境界・更新規約も必要 | Service の Observable を設計 | `Store` / SignalStore | 共有 Service の `signal()` |
| 状態遷移 | 何が起きたかを追跡したい | Action を記録・監視・テストしたい | Subject を自作しても規約は自前 | Action → Reducer / Effect | — |
| 派生 | 1つの値を変換したい | 入力が変わるたび値を作る | `map` | Selector | `computed()` |
| 派生 | 複数の現在状態から値を作りたい | 「最新の現在値」の派生 | `combineLatest(...).pipe(map(...))` | `createSelector` | `computed()` |
| 結合 | 複数の最新値を組み合わせたい | **全入力が最低1回 emit 後**に更新 | `combineLatest` | Effect 内の `combineLatest` 等 | `computed()`（Signal 同士） |
| 結合 | 全処理の完了を待つ | 全入力が complete。1つでも値なし完了なら値は出ず、終わらない入力があれば終わらない | `forkJoin` | Effect 内 `forkJoin` | — |
| 結合 | 同じ順番の値を組み合わせたい | 速い入力の値は相手待ちでバッファされる | `zip` | Effect 内 `zip` | — |
| 結合 | 到着順に1本へ流したい | 値を組にせず、全入力の完了で完了 | `merge` | Effect 内 `merge` | — |
| 最新値参照 | A の発生時だけ B の最新値が欲しい | B が未 emit なら A は流れない。HTTP の結果待ちには使わない | `withLatestFrom` | — | — |
| 最新値参照 | Action を起点に、payload に応じた Store の最新状態を参照したい | Action ごとに selector を遅延生成する。selector は同期的に値を出せること | — | `concatLatestFrom` | — |
| 非同期競合 | 新しい要求を優先したい | 以前の購読を unsubscribe。通信が実際に中断されるかは実装次第 | `switchMap` | Effect + `switchMap` | `resource()` / `httpResource()`（読み取り） |
| 非同期競合 | 全要求を処理したい | 同時実行・結果順不同を許容 | `mergeMap` | Effect + `mergeMap` | — |
| 非同期競合 | 順番を守りたい | 前の完了まで次を開始しない | `concatMap` | Effect + `concatMap` | — |
| 非同期競合 | 実行中の後続を無視したい | 二重送信防止。ただし失われた要求を再実行しない | `exhaustMap` | Effect + `exhaustMap` | — |
| 時間制御 | 入力が止まるまで待つ | 検索欄など | `debounceTime` | Effect 内 `debounceTime` | — |
| 時間制御 | 一定間隔以上では処理しない | スクロール・連打など。先頭／末尾を要件で設定 | `throttleTime` | Effect 内 `throttleTime` | — |
| フィルタ | 条件に合う値だけ通す | イベントや値を選別 | `filter` | Effect 内 `filter` | `computed()` 内で分岐（値を捨てるストリームではない） |
| フィルタ | 同じ値なら処理しない | RxJS は比較関数を指定可。Signal の既定比較は `Object.is` | `distinctUntilChanged` | Observable 側で利用 | `signal({ equal })` |
| 回数制御 | 1回だけ取得したい | `first()` は該当値なしでエラー、`take(1)` はそのまま完了 | `take(1)` / `first()` | Effect 等で利用 | — |
| エラー | エラー後も処理を継続したい | Effect では**内側**で捕捉し、成功／失敗 Action を返す | `catchError` | Effect + `catchError` | Resource の `error()` を表示・処理 |
| エラー | 失敗時に再試行したい | 回数、遅延、対象エラーを決める | `retry` / `retry({ delay })` | Effect + `retry` | `resource.reload()`（明示的再読込） |
| 非同期状態 | loading / value / error を扱いたい | GET 等の読み取り。`value()` はエラー状態で throw するため `hasValue()` 等で守る | 手動で状態化 | Store state として設計 | `resource()` / `httpResource()` |
| 共有 | 同じ Observable 処理を共有したい | `shareReplay` のキャッシュ寿命と `refCount` を明示する | `shareReplay({ bufferSize: 1, refCount: true })` 等 | Store で状態化することが多い | — |
| 購読管理 | Component 破棄時に購読終了したい | 明示的 `subscribe` のとき。注入コンテキスト外では `DestroyRef` を渡す | `takeUntilDestroyed()` | Effects は NgRx が管理 | `toSignal()` は通常自動 cleanup |
| 変換 | Observable を Signal として読む | `toSignal` は即時 subscribe。初期値／`requireSync` とエラー時 throw を設計する | — | Selector Observable にも可 | `toSignal()` |
| 変換 | Signal を Observable に流す | effect 経由のため非同期。同期連続更新は最後の値にまとまる | 変換後に RxJS 処理 | — | `toObservable()` |
| 副作用 | ストリーム途中で副作用を行う | 値を変換しない。購読しなければ実行されない | `tap` | Effect 内 `tap` | — |
| 副作用 | Action を契機に外部処理したい | API、Router、Storage 等。原則として成功／失敗も Action 化 | — | `Effects` | — |
| 副作用 | Signal 変更を外部へ反映したい | state 同期には使わない。effect は非同期に実行される | — | — | `effect()` |

## まず選ぶもの

| 状況 | 第一候補 |
| --- | --- |
| コンポーネント／Service の現在状態を持つ | `signal()` |
| 現在状態から派生値を作る | `computed()` / Selector |
| 複数 Observable の最新値を組み合わせる | `combineLatest` |
| 全 Observable の完了を待つ | `forkJoin` |
| Action の payload に応じた Store の最新値を参照する | `concatLatestFrom` |
| 古い読み取り要求を不要にする | `switchMap` または `httpResource()` |
| Action から API・Router 等を実行する | NgRx Effects |

## 境界ルール

- `BehaviorSubject` は状態を持てる一方、誰でも `next` できる設計にしない。公開するなら原則 `asObservable()` にする。
- `resource()` と `httpResource()` は読み取り向け。`POST` / `PUT` / `DELETE` のような変更処理に使わない。`resource()` の loader で中断を反映するには `AbortSignal` を利用し、`httpResource()` は要求変更時に保留中の HTTP 要求を中断する。
- `combineLatest = computed`、`withLatestFrom = computed` ではない。前者は Observable の emit／完了／エラーという時間的性質を持ち、後者は現在値の依存グラフである。
- `effect()` で Signal 間の状態を同期しない。派生状態は `computed()`、状態更新は明示的なメソッド・イベントに置く。
- Effect 内でエラーを未捕捉にすると、再購読中に Action を取りこぼしうる。内側で失敗 Action または安全な代替 Observable に変換する。
